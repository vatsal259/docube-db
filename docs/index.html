    How it works
    
    
    Codes become paths
    through a trie of chunks.
    
    
    Search walks the trie to prune down to a few candidates, then scores the survivors with Levenshtein and returns the best. A query starting with SHP- never looks at INV- rows.

    Search modes
    
      
    One pipeline, four recall strategies.
    
    
    
    
    
      
    
        
    EXACT
    
        
    Literal match, no trie, no fuzzing. Score 1.0 or nothing.
    
        
    Strict gate, validation
    
      
    
      
    
        
    PREFIX_STRICT
    
        
    Walk the trie exactly; return everything under the matched prefix.
    
        
    Autocomplete, "starts with…"
    
      
    
      
    
        
    TREE_UNTIL_BREAK default
    
        
    Walk exactly until a chunk mismatches, peek fuzzy siblings once, then rank.
    
        
    Scanner / OCR typos, one mistake
    
      
    
      
    
        
    BEAM_WALK
    
        
    Keep several candidate paths open at every chunk, then rank.
    
        
    Multiple typos, scrambled input
    
      
    
    
    
    
    
  
    

  
  
    
    
    
    
    
      
    Quick start
    
      
    No database to install.
    
      
    Requires JDK 21. Jackson is the only runtime dependency.
    
    
    
    
    DocubeDB db = new DocubeDB("/data/codes");

// Create a collection (chunkSize = 4) and load a file in one step
DocubeFile invoices = db.createFileFromRecords(
        "invoices", 4, Path.of("invoices.txt"));

// Default fuzzy search
List<SearchHit> hits = invoices.search(
        "INV-2024-IND-8849Z", 5, 0.85, SearchMode.TREE_UNTIL_BREAK);

SearchHit best = hits.get(0);
System.out.println(best.getText() + " @ " + best.getScore());
